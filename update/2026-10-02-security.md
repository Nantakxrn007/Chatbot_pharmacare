# 2026-10-02 — Data security + หน้า Admin

## สิ่งที่ทำ

- **ปิดช่องรั่ว `/data`**: เดิมใครก็โหลด `users.json`, `chat_history.db`, `chunks.jsonl` ได้โดยไม่ล็อกอิน → ตอนนี้เสิร์ฟเฉพาะ `.pdf` และต้องล็อกอิน (ไฟล์อื่นตอบ 404)
- **Secret / กุญแจ** ใน `.env` (สุ่มใหม่): `JWT_SECRET`, `DATA_ENCRYPTION_KEY`, `BLIND_INDEX_KEY` — ห้ามหาย ห้าม commit
- **Rate limiting**
  - login ผิด 5 ครั้งใน 15 นาที (ต่อ IP+username) → ล็อก 15 นาที; ผิดรวมต่อ IP 20 ครั้งก็ล็อก IP
  - API ทั่วไป 120 req/นาที; chat / สรุปผู้ป่วย / testcase (เรียก LLM) 20 req/นาที
  - เกินแล้วตอบ 429 พร้อม `Retry-After`
- **เข้ารหัสข้อมูล (ยังใช้ SQLite)**
  - เข้ารหัส Fernet (`enc1:`): ชื่อผู้ป่วย, ชื่อแชท, เนื้อหาแชท, patient summary
  - ค้นหาผู้ป่วยผ่าน blind index (HMAC ของชื่อ) จึงยังค้นได้
  - payload ใน Qdrant `chat_memory` เข้ารหัสเนื้อหา (เฉพาะข้อความใหม่)
  - Migration อัตโนมัติตอน start server: สำรอง plaintext ไว้ที่ `backups/` ก่อน → เข้ารหัสข้อมูลเก่า → `VACUUM`
- **Audit log** (`rag/data/audit_log.db`)
  - บันทึก ใคร/ทำอะไร/เมื่อไหร่/IP/ผลลัพธ์ โดยไม่เก็บชื่อผู้ป่วยหรือเนื้อหาแชท
  - append-only (trigger บล็อก UPDATE/DELETE) + hash chain ตรวจการแก้ไขย้อนหลังได้
- **รหัสผ่าน**: PBKDF2-SHA256 600k รอบ (hash เก่ายังใช้ได้ และอัปเกรดเองตอน login สำเร็จ); การสร้างไฟล์ผู้ใช้ใหม่จะสุ่มรหัส admin (หรือใช้ `ADMIN_INITIAL_PASSWORD`)
- **Security headers / cookie**: `nosniff`, `X-Frame-Options`, `Cache-Control: no-store` บน API; `COOKIE_SECURE` + HSTS เปิดเมื่อขึ้น HTTPS
- **หน้า Admin** (`/admin`, เมนู "Admin · Security" ใน sidebar เฉพาะ admin)
  - ภาพรวม: กิจกรรม, login สำเร็จ/ผิด, ถูกจำกัดอัตรา, ถูกปฏิเสธ, ความสมบูรณ์ของ audit log, ผู้ใช้, สถานะการเข้ารหัส, IP ที่ login ผิดบ่อย, รายการที่ถูกล็อก, แถบเตือนค่าตั้งที่ไม่ปลอดภัย
  - ตาราง audit log กรองตามผู้ใช้/action/สถานะ รีเฟรชเองทุก 30 วินาที
  - ตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ทุก request (อ่าน role จาก `users.json` ตอนนั้น); แสดงตัวเลขล้วน ไม่มีชื่อผู้ป่วย/เนื้อหาแชท/hash รหัสผ่าน
  - ถ้ายังไม่ล็อกอิน ระบบจำหน้า `/admin` และพากลับหลังล็อกอิน; ถ้าไม่ใช่ admin จะแจ้งก่อนส่งกลับหน้าแชท

## API ที่เพิ่ม (เฉพาะ admin)

| Endpoint | ใช้ทำอะไร |
|---|---|
| `GET /api/admin/overview` | ตัวเลขสรุปความปลอดภัย |
| `GET /api/admin/audit` | ดู audit log (กรอง `username`, `action`, `status`, `since`, `limit`) |
| `GET /api/admin/audit/verify` | ตรวจว่า audit log ถูกแก้ไขหรือไม่ |

`/api/me` คืนค่า `role` เพิ่ม

## ทดสอบแล้ว (บนสำเนาโปรเจกต์)

- `/data/users.json`, `.db`, `.jsonl`, `.md` ตอบ 404; PDF ต้องล็อกอิน
- ข้อความทั้ง 484 ข้อความ ถอดรหัสกลับตรงเดิม; รายชื่อผู้ป่วยของทุก user ตรงเดิม; ไม่เหลือชื่อผู้ป่วยแบบ plaintext ในไฟล์ DB
- login ผิดครบ → 429 แม้ใส่รหัสถูก; API เกินโควตา → 429
- audit chain ตรวจผ่าน, ลบ/แก้แถวไม่ได้, ไม่มีชื่อผู้ป่วยใน log
- `/api/admin/*`: admin ได้ 200, user ธรรมดา 403
- frontend build ผ่าน (tsc + vite)

## ต้องทำต่อ / ข้อควรระวัง

- **เปลี่ยนรหัส `admin` จาก `123`** (บัญชีเดิมยังใช้รหัสเดิม) — ยังไม่มีหน้าเปลี่ยนรหัสผ่าน
- **สำรอง `DATA_ENCRYPTION_KEY` / `BLIND_INDEX_KEY` นอกเครื่อง** — กุญแจหาย = ข้อมูลที่เข้ารหัสกู้ไม่ได้
- **ลบไฟล์ใน `backups/`** หลังตรวจข้อมูลถูกต้อง (เป็น plaintext)
- **HTTPS ยังไม่ได้ทำ**: localhost ไม่ต้องใช้; ตอน deploy GCP VM ใช้ Caddy + โดเมน (ซื้อ หรือ subdomain ฟรีเช่น DuckDNS) แล้วตั้ง `COOKIE_SECURE=true`, `TRUST_PROXY_HEADERS=true`
- ข้อความเก่า 423 จุดใน Qdrant Cloud `chat_memory` ยังเป็น plaintext (เข้ารหัสเฉพาะข้อความใหม่)
- `chat_history.db` / `users.json` ยังถูก track ใน git — ข้อมูลผู้ป่วยเก่าอยู่ในประวัติ git
- rate limiter เก็บในหน่วยความจำ เหมาะกับ uvicorn 1 worker (รีสตาร์ทแล้วนับใหม่)
- ข้อความแชทยังถูกส่งให้ LLM (Gemini/Typhoon) ประมวลผลตามปกติ
