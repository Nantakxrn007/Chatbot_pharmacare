## 2. ตรวจของเดิมก่อนแก้ (อ่านอย่างเดียว) -- ยืนยันต้นเหตุจริง

### 2.1 ต้นเหตุข้อ 1-2: คลังยาใน Context ไม่เคยรู้จัก "ยาที่ผู้ป่วยแพ้"

รันโค้ดเดิมกับข้อความเคส 1 และ 2 แล้วพิมพ์ `DOSE CATALOG` ที่ระบบส่งเข้า Context ออกมาดู:

```
==== CASE1  feat = {'renal': True, 'paracetamol_failed': False, 'group': 'adult'}
 ยาแก้ปวด/ลดไข้ ... -- เหมาะกับเคสนี้: มีไข้/ปวด/เจ็บคอ
  [ยาหลัก]
  - Paracetamol (Page: 8) | ...
  [ทางเลือกในกลุ่ม (เช่น NSAIDs -- ตรวจข้อห้าม)]
  - Ibuprofen [NSAID] (Page: 10) | ขนาดผู้ใหญ่: 200 to 400 mg every 4 to 6 hours ...   <-- ยาที่ผู้ป่วยแพ้
IBUPROFEN in catalog: True

==== CASE2  feat = {'renal': None, 'paracetamol_failed': True, 'group': 'adult'}
 ยาแก้ปวด/ลดไข้ ... -- ใช้ Paracetamol แล้วไม่ดีขึ้น: **พิจารณายาแก้ปวดกลุ่ม NSAIDs เป็นทางเลือก**
  - Ibuprofen [NSAID] (Page: 10) | ...
  - Diclofenac [NSAID] (Page: 12) | ...
IBUPROFEN in catalog: True
```

**สรุปต้นเหตุ (ไม่ใช่ "โมเดลมั่ว" แต่เป็น "ระบบยื่นยาที่แพ้ให้โมเดลเอง"):**

1. `extract_case_features()` **ไม่มีฟิลด์ประวัติแพ้ยา** เลย -- ระบบสกัดได้แค่ "อาการ" กับ "โรคร่วม"
2. `build_catalog()` จึงลง **Ibuprofen พร้อมขนาดยาตรงจากตาราง** เป็น "ทางเลือกในกลุ่ม" ตามปกติ
   -> โมเดลลอกตามคลังยาที่ระบบยื่นให้ = **ไม่ใช่ hallucination แต่เป็นข้อมูลที่ระบบป้อนเข้าไปเอง**
3. **เคส 2 หนักกว่าเพราะระบบ "ชี้ทาง" ไปที่ยาที่แพ้พอดี**: `paracetamol_failed=True` ทำให้เหตุผลของกลุ่ม
   กลายเป็น *"ใช้ Paracetamol แล้วไม่ดีขึ้น: พิจารณายาแก้ปวดกลุ่ม NSAIDs เป็นทางเลือก"* -- ซึ่งกลุ่มนั้น
   คือกลุ่มที่ผู้ป่วยแพ้ => ตรงกับที่อาจารย์สังเกตว่า **"แค่ปรับรูปแบบคำถามนิดหน่อย ทำให้ LLM ไขว้เขว"**
4. เคส 3 ที่ตอบถูก **ไม่ได้ถูกเพราะมี gate** -- ถูกเพราะโมเดล "บังเอิญ" ให้เหตุผลเองว่าแพ้ทั้ง Paracetamol
   และ Ibuprofen จึงต้องเลี่ยงทั้งกลุ่ม => เป็นความบังเอิญ ไม่ใช่การรับประกัน

### 2.2 ต้นเหตุข้อ 4: กรอบ Expert Opinion ว่าง -- เป็นบั๊กการห่อ DOM ฝั่งเว็บ

`frontend/react-app/src/components/MarkdownMessage.tsx` -> `applyExpertBlocks()` ห่อบล็อกโดย
ไล่เก็บ element ถัดจากหัวข้อ แล้ว **หยุดทันที** เมื่อเจอหัวข้อย่อยตัวหนาที่ขึ้นต้นด้วยคำว่า "ยา"
(`TREATMENT_SUBLABEL_PATTERN = /^ยา\S/`) เพราะถือว่าเป็นหัวข้อยาของส่วนการรักษาปกติ

```ts
let node = block.nextElementSibling;
while (node && !/^H[1-4]$/.test(node.tagName)) {
  const label = node.querySelector(':scope > strong:first-child');
  if (label && TREATMENT_SUBLABEL_PATTERN.test(label.textContent || '')) break;   // <-- หยุดตั้งแต่ตัวแรก
  block.appendChild(node);
  node = next;
}
```

=> ถ้าโมเดลเขียน **บรรทัดแรกใต้หัวข้อบล็อกเป็นหัวข้อย่อยตัวหนา** เช่น `**ยาทางเลือกแรก (First-line):**`
หรือ `**ยาปฏิชีวนะที่พิจารณาจ่าย:**` (ซึ่งพบบ่อยมาก) เงื่อนไขนี้จะยิงตั้งแต่ node แรก
**ยังไม่ได้เก็บอะไรเข้ากรอบเลย** -> ได้กรอบเขียว + tag + หัวข้อ แล้วเนื้อหาทั้งหมดตกไปอยู่นอกกรอบ
= ตรงกับที่อาจารย์เห็นเป๊ะ ("เหมือนมันถูกตัดออกไป มีแต่กรอบสีเขียวกับหัวข้อ ... หรือไม่ก็ข้อมูลอยู่นอกกรอบ")

*(ตรวจแล้วว่าไม่ใช่ฝั่ง backend ตัดทิ้ง: `_postprocess_answer` / `_stream_flush` / sanitizer ไม่มีตัวใดลบบรรทัดใต้หัวข้อนี้)*

### 2.3 ต้นเหตุที่เจอเพิ่มระหว่างทดสอบ: บริบทเคสหายเมื่อผู้ใช้เปลี่ยนสำนวน

ทดสอบเคสใกล้เคียง `"ชายอายุ 45 ปี เจ็บคอ ไข้ 38.5 องศา ไอเล็กน้อย แพ้ยากลุ่ม NSAIDs"`
แล้วเทิร์นถัดมาถามว่า `"ขอตัวเลือกยาแก้ปวดลดไข้ทั้งหมดที่มีในร้านครับ"` -> ระบบ **ทิ้งเคสเดิมทั้งก้อน**
แล้วไปซักประวัติใหม่ตั้งแต่ต้น (ถามอายุ/ประวัติแพ้ยาซ้ำ ทั้งที่เพิ่งบอกไป):

```
gate mode: ask
gate case_text: ขอตัวเลือกยาแก้ปวดลดไข้ทั้งหมดที่มีในร้านครับ   <-- เคสเดิมหายหมด
gate feat allergy: {'drugs': [], 'tags': set()}
```

**เหตุผล:** ชื่อกลุ่มยาในภาษาไทยมีคำอาการอยู่ในตัว -- `"ยาแก้ปวดลดไข้"` ทำให้ตัวสกัดอาการเจอ
"ปวด" + "ไข้" -> `is_case_description()` ตัดสินว่าเป็น **"คำบรรยายเคสของผู้ป่วยรายใหม่"**
-> `history_gate()` เลยถือว่าเป็นคนไข้คนละคน แล้วตัดบริบทเดิม (รวมประวัติแพ้ยา) ทิ้ง
= นี่คือ **"context ที่หายไปกลางทาง"** และ **"คำถามหลอก"** ที่อาจารย์พูดถึง ในรูปแบบที่วัดได้

## 3. สิ่งที่ทำ (แก้เฉพาะจุด -- 3 ไฟล์ +441/-16 บรรทัด)

### 3.1 Drug-allergy gateway -- กัน 3 ชั้น (`backend/symptomatic_gateway.py`)

หลักการ: **ระบบต้องรู้จัก "ยาที่ผู้ป่วยแพ้" แบบ deterministic** ไม่ฝากความปลอดภัยไว้กับการให้เหตุผลของโมเดล

**ชั้นที่ 0 -- สกัดชื่อยาที่แพ้** (`extract_drug_allergies` / `allergy_profile`)

อ่านเฉพาะ "รายการยาที่ต่อจากคำว่าแพ้" ด้วยการไล่โทเคน (ตัวคั่น -> ชื่อยา -> ตัวคั่น -> ชื่อยา ...)
หยุดทันทีที่เจอคำที่ไม่ใช่ทั้งสองอย่าง -- จึงไม่ไปจับยาที่อยู่คนละประโยค:

| ข้อความ | ผลลัพธ์ | เหตุผล |
|---|---|---|
| `แพ้ยา Ibuprofen ใช้พาราไม่ดีขึ้นเลย` | `['Ibuprofen']` | **ไม่เอา Paracetamol** เพราะอยู่คนละอนุประโยค (คำว่า "ใช้" ตัดจบรายการ) |
| `มีประวัติแพ้ยา Ibuprofen และมีโรคประจำตัวเป็นโรคไต` | `['Ibuprofen']` | "และมีโรคประจำตัว" ไม่ใช่ชื่อยา -> จบรายการ |
| `มีประวัติแพ้ยา Ibuprofen, paracetamol` | `['Ibuprofen','Paracetamol']` | `,` เป็นตัวคั่นในรายการเดียวกัน |
| `ไม่มีประวัติแพ้ยา` / `ปฏิเสธการแพ้ยา` / `NKDA` / `ไม่ทราบประวัติแพ้ยา` | `[]` | มี deny-guard |
| `เป็นภูมิแพ้ แพ้อากาศ แพ้ฝุ่น` / `แพ้อาหารทะเล` | `[]` | ไม่ใช่การแพ้ยา |
| `มีประวัติแพ้ยา ไอบูโพรเฟน` | `['Ibuprofen']` | รองรับชื่อยาภาษาไทย |

พจนานุกรม 27 รายการ (ไทย+อังกฤษ) พร้อมแท็กกลุ่มสำหรับ cross-reactivity:
`nsaid` / `paracetamol` / `beta_lactam` / `macrolide` / `sulfa`
แล้วผูกเข้า `extract_case_features()` เป็นฟิลด์ `f["allergy"]` -> **ติดไปกับ features ทุกเทิร์นของเคสนั้น**

**ชั้นที่ 1 -- ตัดออกจากคลังยาที่ส่งเข้า Context** (`allergy_drug_block` ใน `build_catalog`)

ตรวจก่อนข้อพิจารณาอื่นทั้งหมด และตัดออก 3 กรณี:

1. **ยาตัวนั้นเอง** (เทียบกับชื่อในตาราง + ตัวยาสำคัญของผลิตภัณฑ์ -> ครอบยาสูตรผสมอย่าง Decolgen/TIFFY ด้วย)
2. **cross-reactivity ในกลุ่ม NSAIDs** -- แพ้ตัวหนึ่ง = เลี่ยงทั้งกลุ่ม (COX-1 mediated hypersensitivity
   เป็น cross-reactive ระดับกลุ่ม ซึ่งตรงกับคำตอบที่ถูกต้องของ Case 3 ที่อาจารย์ยกมา)
3. **ผลิตภัณฑ์นอกหมวดยาแก้ปวดที่มีตัวยา NSAID** -- เช่น `Strepsils Maxpro (มีตัวยา flurbiprofen)`
   ซึ่งธง `nsaid` เดิมจับไม่ได้เพราะอยู่ในหมวดยาอม

> **เจตนา:** จำกัด cross-reactivity ไว้ที่ **กลุ่ม NSAIDs เท่านั้น** -- ส่วน beta-lactam ยังปล่อยให้
> ตรรกะเดิม (`allergy_note()` ที่แยก type 1 / non-type 1) ตัดสินตามเดิม เพราะ cephalosporin
> **ยังเป็นทางเลือกที่ถูกต้อง** ในการแพ้แบบไม่รุนแรง -- เหมาถือว่าห้ามหมดจะทำให้ของเดิมที่ถูกอยู่แล้วแย่ลง

ผลกับเคสตามโจทย์ (รันจริง):

| เคส | `f["allergy"]` | กลุ่มยาแก้ปวด/ลดไข้ใน Context |
|---|---|---|
| Case 1 | `{'drugs': ['Ibuprofen'], 'tags': {'nsaid'}}` | เหลือ **Paracetamol ตัวเดียว**; NSAIDs ทั้ง 8 ตัวย้ายไปอยู่รายการ "ไม่แนะนำในเคสนี้" พร้อมเหตุผล |
| Case 2 | `{'drugs': ['Ibuprofen'], 'tags': {'nsaid'}}` | เหมือนกัน + เหตุผลของกลุ่มเปลี่ยนเป็น *"ใช้ Paracetamol แล้วไม่ดีขึ้น **แต่ผู้ป่วยแพ้ NSAIDs จึงห้ามใช้ NSAIDs แทน**"* |
| Case 3 | `{'drugs': ['Ibuprofen','Paracetamol'], 'tags': {'nsaid','paracetamol'}}` | **ไม่เหลือยาในกลุ่มเลย** -> ระบบใส่บรรทัดสั่งชัดเจนว่าให้เลี่ยงทั้งกลุ่ม เสนอทางเลือกไม่ใช้ยา + ส่งต่อแพทย์ และ **ห้ามหยิบชื่อยานอก catalog มาเติมเอง** |

**ชั้นที่ 2 -- บันทึกข้อห้ามให้ LLM ทุกเทิร์น** (`allergy_gate_note`)

ใส่ใน `clinical_notes` **ทุกเทิร์น รวมคำถามต่อเนื่อง** (ไม่ใช่เฉพาะเทิร์นที่ผู้ใช้พิมพ์คำว่า "แพ้")
-- นี่คือจุดที่เคสเดิมพัง เพราะเทิร์นที่ 3 เป็น follow-up ที่ไม่มีคำว่าแพ้อยู่ในข้อความ

**ชั้นที่ 3 -- ตรวจคำตอบก่อนส่งถึงผู้ใช้** (`audit_allergy_lines`)

ทำงานระดับบรรทัด จึงใช้ได้ทั้งโหมดสตรีมและไม่สตรีม -- บรรทัดที่ **"เสนอ"** ยาที่แพ้
(ชื่อยาขึ้นต้นบรรทัด/ต้นช่องตาราง และ **ไม่มีคำเตือนกำกับ**) จะถูกแทนด้วยบรรทัดเตือน
พร้อมตัดบรรทัดย่อย "ขนาด: ..." ที่ห้อยอยู่ใต้ยานั้นออกไปด้วย (ไม่ให้ขนาดยาค้างแบบไม่มีหัวเรื่อง):

```
ก่อน:  - **Ibuprofen**: ยาในกลุ่ม NSAIDs ใช้ลดไข้และแก้ปวด [Ref: Dose, หน้า 10]
         - ขนาด: 200-400 mg ทุก 4-6 ชั่วโมง [Ref: Dose, หน้า 10]
หลัง:  - ~~Ibuprofen~~ **ห้ามใช้ในผู้ป่วยรายนี้ -- มีประวัติแพ้ยา Ibuprofen** (ระบบตัดออกอัตโนมัติเพื่อความปลอดภัย)

ก่อน:  | Ibuprofen | 200-400 mg ทุก 4-6 ชม. | ตามอาการ | ระวังในโรคไต |
หลัง:  | Ibuprofen | - | - | **ห้ามใช้ในผู้ป่วยรายนี้ -- มีประวัติแพ้ยา Ibuprofen** (ระบบตัดออก...) |
```

**สิ่งที่ตัวตรวจนี้ตั้งใจ "ไม่แตะ"** (ทดสอบแล้วทุกข้อ):
- บรรทัดที่พูดถึงยานั้นในเชิงเตือนอยู่แล้ว (`หลีกเลี่ยงการใช้ Ibuprofen เนื่องจากมีประวัติแพ้`)
- บรรทัดที่เอ่ยชื่อยากลางประโยค (`- Paracetamol เป็นทางเลือกแทน NSAIDs`) -- ต้องขึ้นต้นบรรทัดเท่านั้น
- **เคสที่ไม่มีประวัติแพ้ยา -> ไม่แตะคำตอบเลยแม้แต่ตัวอักษรเดียว** (ยืนยันด้วย unit test)

### 3.2 Expert Opinion integrity gateway -- แก้ทั้งสองฝั่ง

**ฝั่งเว็บ** (`MarkdownMessage.tsx`, +12/-4): ห้ามปิดกรอบก่อนเก็บเนื้อหาเข้าไปอย่างน้อย 1 ก้อน

```ts
let absorbed = 0;
while (node && !/^H[1-4]$/.test(node.tagName)) {
```

### 3.4 กฎใหม่ใน SYSTEM PROMPT (ข้อ 5.1 -- SAFETY RULE)

เพิ่มหัวข้อ *"ประวัติแพ้ยาของผู้ป่วย = ข้อห้ามเด็ดขาด"* ก่อนข้อ 6 (ห้าม Hallucinate) ครอบ 6 ประเด็น:
ห้ามปรากฏเป็นคำแนะนำในทุกหัวข้อ / **ประวัติแพ้ยาผูกกับผู้ป่วย ไม่ใช่ผูกกับเทิร์น** /
แพ้ NSAID ตัวหนึ่ง = เลี่ยงทั้งกลุ่ม / **"ใช้ยา X แล้วไม่ได้ผล" ห้ามลบล้างข้อห้ามเรื่องการแพ้** /
เอ่ยได้เฉพาะเชิงห้ามใช้ / **บังคับไล่ตรวจชื่อยาทุกตัวก่อนปิดคำตอบ** (= "make sure ก่อนตอบ")

### 3.5 (feedback รอบเก็บรายละเอียด) ยาที่ "ใช้มาแล้วไม่ได้ผล" ต้องไม่ถูกเสนอซ้ำ

**อาการที่อาจารย์แจ้ง:** เคส *"แพ้ยา Ibuprofen **ใช้พาราไม่ดีขึ้นเลย**"* -- ระบบตัด NSAIDs ออกถูกแล้ว
แต่ตอนถามยาแนะนำยังเสนอ **Paracetamol** กลับมา ทั้งที่โจทย์บอกว่าใช้แล้วไม่ดีขึ้น
(ส่วนเคสที่เขียนว่า "แพ้ Ibuprofen, paracetamol" ตรงๆ ไม่มีปัญหา เพราะเข้าเส้นทางประวัติแพ้ยา)

**ต้นเหตุ (ยืนยันด้วยการรันโค้ดเดิม):** ระบบ**รู้อยู่แล้ว**ว่า `paracetamol_failed=True` แต่เอาไปใช้
แค่เขียน "เหตุผล" ของกลุ่มยา -- **ไม่ได้ตัด Paracetamol ออกจาก DOSE CATALOG** พอ NSAIDs ถูกตัดด้วย
การแพ้ Paracetamol จึงเหลือเป็นตัวเลือกเดียวที่ระบบยื่นให้โมเดล โมเดลก็เสนอตาม

**การแก้ -- ใช้กลไกชุดเดียวกับ gateway การแพ้ยา (ไม่ได้สร้างของใหม่):**

| ชั้น | ทำอะไร |
|---|---|
| `extract_failed_drugs()` | สกัด "ยาที่ใช้มาแล้วอาการไม่ดีขึ้น" แบบ deterministic จับสองทิศทาง ("ใช้พาราไม่ดีขึ้นเลย" / "อาการไม่ดีขึ้นหลังกิน paracetamol") |
| `failed_drug_block()` | ตัดออกจาก DOSE CATALOG เหมือนยาที่แพ้ (ใน `build_catalog`) |
| `prior_failed_note()` | บันทึกให้ LLM ทุกเทิร์น (ผูกกับเคส ไม่ใช่ผูกกับเทิร์น) |
| `rag_engine` | กันโน้ตเดิม *"ต้องใส่ Paracetamol ในหัวข้อ 3b"* ไม่ให้ตีกับกฎใหม่ |

**ยืดหยุ่นแค่ไหน -- ไม่ใช่เฉพาะพารา (ข้อกังวลของอาจารย์):**
เดิมตัวจับชื่อยาเป็น**พจนานุกรมเขียนมือ 26 ตัว** ทำให้ *"ทาน Bromhexine มาแล้วไม่ดีขึ้น"* หลุด
-> เปลี่ยนเป็น **data-driven: ดึงชื่อยาจากตาราง Dose เอง** (53 ตัว) รวมกับพจนานุกรม (ชื่อไทย/ชื่อพ้อง/
ยาปฏิชีวนะที่ไม่ได้อยู่ในตาราง) = ตัวจับ **66 รายการ** -- ถ้าตาราง Dose เพิ่ม/ลดยา ตัวจับครอบตามเองโดยไม่ต้องแก้โค้ด
และใช้กับ **ทั้งเส้นทาง "ใช้แล้วไม่ได้ผล" และเส้นทาง "แพ้ยา"**

**กุญแจกันตีความผิด 3 ดอก:**
1. **มีคำว่า "ดีขึ้น/ทุเลา/ลดลง/บรรเทา" คั่นอยู่ = ยาได้ผล ห้ามตัด** -- *"ใช้พาราแล้ว**ดีขึ้น**มาก แต่ยังเจ็บคออยู่"*
   (เจอ bug นี้ตอนรันจริงแล้วแก้ -- เดิมถูกอ่านว่าล้มเหลวเพราะไปเจอคำว่า "ยังเจ็บ")
2. **ตัดที่ขอบประโยค** -- *"ใช้ Bromhexine แล้วดีขึ้น. ส่วน Paracetamol ไม่ดีขึ้น"* -> โทษเฉพาะ Paracetamol
3. **จำกัดเฉพาะยาที่อยู่ในตาราง Dose** -- ยาปฏิชีวนะมี `prior_antibiotic_note()` ดูแลอยู่แล้ว
   ถ้าเอากฎ "ห้ามเสนอซ้ำ" ไปทับ จะไปห้าม **Amoxicillin/clavulanate** ซึ่งเป็นคำตอบที่ถูกต้องของเคส AOM

> **ทำไมไม่ใช้ LLM ช่วยตีความ:** ยาที่ระบบ "เสนอได้จริง" มีเพียงยาในตาราง Dose เท่านั้น การดึงชื่อจาก
> ตารางเองจึงครอบพื้นที่ที่มีผลต่อคำตอบได้ **100% ด้วย latency 0** -- ส่วน LLM จะเพิ่ม ~1-2 วินาที/เทิร์น
> โดยไม่ได้ coverage เพิ่ม (ยาที่ไม่อยู่ในตาราง ระบบก็เสนอไม่ได้อยู่แล้ว)

| **Case 1 turn 3** | `Ibuprofen: ยาในกลุ่ม NSAIDs ใช้ลดไข้และแก้ปวด 📄 Dose p.10` / `ขนาด: 200-400 mg ทุก 4-6 ชั่วโมง` + `Diclofenac 100-150 mg/วัน` | เหลือ **Paracetamol ตัวเดียว** พร้อมหมายเหตุ: *"ห้ามใช้ Ibuprofen, Diclofenac, Naproxen, Mefenamic acid, Aspirin, Piroxicam, Celecoxib และ Etoricoxib เนื่องจากผู้ป่วยมีประวัติแพ้ Ibuprofen ... | **Case 4 (Expert Opinion)** | กรอบเขียว + หัวข้อ แต่ **ไม่มีเนื้อหา** | ทุกบล็อกมีเนื้อหาในกรอบครบ (**0 กรอบเปล่า** จาก 159 เทิร์น) ตัวอย่างจริง: *"**ในทางปฏิบัติจริงของไทย ไซนัสอักเสบ แม้มีอาการติดต่อกันไม่ถึง 10 วัน สามารถพิจารณาจ่ายยาปฏิชีวนะได้เลย...** โดยยาทางเลือกแรกคือ **Amoxicillin/clavulanate (Augmentin) 500 mg ทุก 8 ชั่วโมง...**"* |

### 4.4 ผลการตรวจฝั่งเว็บ (DOM test ด้วยฟังก์ชันตัวจริงจากไฟล์)

สไลซ์ `applyExpertBlocks()` **ออกมาจาก `MarkdownMessage.tsx` โดยตรง** (ไม่ได้พิมพ์โค้ดซ้ำ)

## 6. ข้อจำกัด / ความเสี่ยงที่เหลือ

1. **พจนานุกรมชื่อยาที่แพ้มี 27 รายการ** -- ครอบยาที่พบใน URI/ร้านยาและยาปฏิชีวนะหลัก
   ถ้าผู้ใช้พิมพ์ชื่อยานอกรายการ (เช่น ยาโรคเรื้อรังที่ไม่เกี่ยวกับ URI) ชั้นที่ 1-3 จะไม่ยิง
   แต่ **ชั้นที่ 2 (กฎใน SYSTEM PROMPT) ยังทำงาน** -> ไม่ถอยหลังจากของเดิม; เพิ่มรายการได้ที่
   `_ALLERGEN_LEXICON` ใน `symptomatic_gateway.py` (เพิ่มบรรทัดเดียวต่อยาหนึ่งตัว)
2. **cross-reactivity บังคับเฉพาะกลุ่ม NSAIDs** -- beta-lactam ยังใช้ตรรกะเดิมที่แยก type 1 / non-type 1
   (ตั้งใจ เพราะ cephalosporin ยังเป็นทางเลือกที่ถูกต้องในการแพ้แบบไม่รุนแรง)
3. **`ensure_expert_block` เติมประโยคนำเมื่อกรอบจะว่าง** -- ข้อความที่เติมเป็น **ถ้อยคำต้นฉบับจาก AAFP**
   (เจ็บคอ = RDU Practice หน้า 4 / ไซนัส = Note on Thai Clinical Practice หน้า 5) ส่วนเคสอื่นเติมได้
   เฉพาะประโยคกรอบความคิดที่ไม่มีเนื้อหาทางคลินิก -- ตรวจซ้ำบนคำตอบจริงทั้ง **154 ชุดแล้ว
   ไม่มีชุดใดถูกแก้เลย (0/154)** ตัวนี้จึงเป็น safety net ล้วนๆ ที่ยังไม่เคยทำงานจริง
4. **ความแกว่งของ LLM ยังมี** -- ชั้นที่ 1 (คลังยา) และชั้นที่ 3 (ตรวจคำตอบ) เป็น deterministic
   จึงไม่แกว่ง แต่ *ถ้อยคำอธิบาย* ยังต่างกันได้ในแต่ละครั้ง
5. **ฝั่งเว็บ**: ถ้าโมเดลเขียนหัวข้อย่อย `**ยา...**` ต่อจากประโยคนำภายในบล็อก บล็อกยังถูกปิดตรงนั้น
   (พฤติกรรมเดิม ไม่ได้เปลี่ยน) -- แต่ **จะไม่เกิดกรอบเปล่าอีกแล้ว** ซึ่งเป็นอาการที่อาจารย์แจ้ง
