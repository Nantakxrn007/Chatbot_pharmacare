## 2. ตรวจของเดิมก่อนแก้ (อ่านอย่างเดียว) -- ยืนยันสาเหตุจริงทั้ง 3 ข้อ

รันเคสทั้งสามผ่านชั้น gateway แบบ deterministic (ไม่เรียก LLM) บนโค้ดเดิม ได้ผลตรงกับที่อาจารย์เจอทุกข้อ:

| เคส | ผลของโค้ดเดิม | Root cause (บรรทัดจริง) |
|---|---|---|
| 1 | `plan["antihistamine"] = ('avoid', 'น้ำมูกข้นเหนียว -- ยาแก้แพ้ (โดยเฉพาะรุ่นที่ 1 ...)')` | `plan_classes()` ตัดสิน **ทั้งกลุ่มยา** เป็นค่าเดียว (fit/conditional/avoid) ไม่มีกลไก "กลุ่มใช้ได้ แต่บางตัวในกลุ่มไม่เหมาะ" -> `build_catalog()` ยก **ทุกตัวในกลุ่ม** ไปอยู่ใต้หัวข้อ "ไม่เหมาะกับเคสนี้" และ `gate_dose_chunks()` ตัด chunk ของ Cetirizine/Loratadine ทิ้งจาก Context ด้วย -- โมเดลจึงไม่มีทางเสนอรุ่นที่ 2 ได้เลย |
| 2 | เหตุผลข้อแพ้ยาลงท้ายด้วย `"...ใช้ยากลุ่ม cephalosporin แทนได้หรือไม่"` | ข้อความ hard-code อยู่ใน `history_checklist()` (คำถาม+เหตุผลของเทิร์นซักประวัติเป็น deterministic ทั้งหมด) -- และยังมีจุดอื่นที่ยกตัวอย่างยาในเหตุผลอีก (โรคประจำตัว -> "ยาแก้คัดจมูกในความดันสูง, NSAIDs ในโรคไต", AOM -> "เคยได้ amoxicillin ใน 30 วัน") |
| 3 | `centor_assessment()` -> `applicable: True`, ถามต่อ "มีไอไหม / ต่อมน้ำเหลือง" โดยอ้างว่าเป็นเกณฑ์ Centor | ประตูเดียวของ Centor คือ `if not f.get("sore_throat"): return None` -- เคส laryngitis มี "เจ็บคอ/เยื่อบุคอแดง" จึงติด `sore_throat=True` แล้วเข้าเกณฑ์ไปโดยปริยาย |

**ตรวจ Context จริงว่า AAFP พูดว่าอย่างไร (`rag/data/AAFP.md`)**
- หน้า 4: *"...recommend using the modified Centor criteria **when evaluating patients with pharyngitis** to determine the likelihood of group A beta-hemolytic streptococcal infection"* -> **Centor ผูกกับ pharyngitis เท่านั้น**
- TABLE 1: `Laryngitis | Hoarse voice, sore throat, nasal congestion, fever | **Supportive care**` (ไม่มี Centor, ไม่มี ATB)
- หัวข้อ Laryngitis: *"Antibiotics in the treatment of laryngitis should be avoided."*
-> การตัด Centor ออกจากเคส laryngitis **เป็นไปตาม Context ตรงตัว ไม่ใช่การเดา**

## 3. สิ่งที่ทำ (แก้เฉพาะจุด ไม่ refactor)

### 3.1 แก้ข้อ 1 -- ยาแก้แพ้: แยก "รุ่นที่ 1" ออกจาก "ทั้งกลุ่ม"

เพิ่ม **status ใหม่ `partial`** (กลุ่มยังใช้ได้ แต่บางตัวในกลุ่มไม่เหมาะ) แทนที่จะเหมาเป็น `avoid` ทั้งกลุ่ม:

| จุดที่แก้ | เดิม | ใหม่ |
|---|---|---|
| `plan_classes()` (น้ำมูกข้นเหนียว) | `("avoid", "ยาแก้แพ้ ... ไม่เหมาะ")` | `("partial", "รุ่นที่ 1 (CPM, Brompheniramine) ไม่เหมาะ ... **รุ่นที่ 2 ยังใช้ลดน้ำมูกได้** ควบคู่กับล้างจมูกด้วยน้ำเกลือ")` |
| `class_drug_block()` **(ฟังก์ชันใหม่ 8 บรรทัด)** | -- | คืนเหตุผลกันเฉพาะ "ตัวยา" ที่ไม่เหมาะในกลุ่มนั้น (กฎเดียวตอนนี้: `first_gen` + น้ำมูกข้นเหนียว + ไม่ใช่เคสภูมิแพ้) |
| `build_catalog()` | ทั้งกลุ่มไปอยู่ใต้ "ไม่เหมาะกับเคสนี้" | รุ่นที่ 2 อยู่ใน `[ยาหลัก]` พร้อมขนาด+หน้า, รุ่นที่ 1 ไปอยู่บรรทัด "มีในตารางแต่ไม่แนะนำในเคสนี้ -- เหตุผล ..." |
| `gate_dose_chunks()` | ตัด chunk ยาแก้แพ้ทั้งกลุ่ม | ตัดเฉพาะตัวที่ถูกกันระดับตัวยาในทุกกลุ่มที่เกี่ยวข้อง |
| SYSTEM prompt (หลักเภสัชวิทยา) | "น้ำมูกข้นเหนียว -> ไม่ใช้ Antihistamine รุ่นที่ 1 -> แนะนำล้างจมูก" | เพิ่ม **"รุ่นที่ 2 ยังใช้ได้"** + **ห้ามเขียนเหมารวมทั้งกลุ่ม และห้ามใส่ Cetirizine/Loratadine ไว้ในรายการ 'ไม่เหมาะกับเคสนี้' เด็ดขาด** |
| SYSTEM prompt (ใหม่) | -- | **กฎสมดุล**: ถ้าคำตอบเอ่ยชื่อยาว่า "ไม่เหมาะ" ต้องเอ่ยชื่อตัวเลือกที่ "ใช้ได้" ในกลุ่มเดียวกัน พร้อมขนาด + `[Ref]` ในคำตอบเดียวกันเสมอ (ห้ามบอกแต่ตัวที่ห้ามแล้วผลักตัวที่ใช้ได้ไปให้ถามต่อ) |

> กฎนี้เป็น **ความรู้ระดับกลุ่มยา ไม่ใช่ hard-code รายเคส** -- ใช้กับทุกเคสน้ำมูกข้นเหนียว/ไซนัสอักเสบโดยอัตโนมัติ
> และ **ไม่กระทบเคสน้ำมูกใส** (รุ่นที่ 1 ยังถูกเสนอเป็นตัวเลือกตามเดิม -- ทดสอบแล้วในข้อ 4)

### 3.2 แก้ข้อ 2 -- ขั้นซักประวัติไม่ยกตัวอย่างยา

แก้ข้อความ deterministic ใน `history_checklist()` / `history_gaps()` + เพิ่มกฎบังคับใน SYSTEM prompt (กัน LLM เติมเอง):

| คำถาม | เหตุผลเดิม | เหตุผลใหม่ |
|---|---|---|
| ประวัติแพ้ยา | "...ชนิดของอาการแพ้เป็นตัวกำหนดว่าใช้ยากลุ่ม **cephalosporin** แทนได้หรือไม่" | "...**ชนิดและความรุนแรงของอาการแพ้เป็นตัวกำหนดว่าจะเลือกยาปฏิชีวนะทางเลือกกลุ่มใดได้บ้าง**" |
| โรคประจำตัว (ผู้ใหญ่) | "...เช่น **ยาแก้คัดจมูก**ในความดันสูง, **NSAIDs** ในโรคไต/แผลในกระเพาะ/หอบหืด" | "...**เพราะโรคประจำตัวบางอย่างเป็นข้อห้ามหรือต้องปรับขนาดยา**" |
| โรคประจำตัว (เด็ก) | "...เช่น **NSAIDs** ในหอบหืด และผลิตภัณฑ์บางชนิดในผู้ที่เป็น G6PD" | "...**ซึ่งโรคประจำตัวบางอย่างเป็นข้อห้ามของยาบางกลุ่ม**" |
| ยาที่ใช้มาก่อน (เคส AOM) | "...ถ้าเคยได้ **amoxicillin** ใน 30 วัน จะเปลี่ยนยาตัวแรก" | "...**ยาปฏิชีวนะที่เคยได้ภายใน 30 วันมีผลต่อการเลือกยาตัวแรก**" |
| ลักษณะน้ำมูก | "...น้ำมูกข้นเหนียวไม่ควรใช้ **antihistamine รุ่นที่ 1** ... ควรล้างจมูกแทน" | "...น้ำมูกใสเหลว/ไหลเป็นสาย กับน้ำมูกข้นเหนียว **ใช้ยาคนละแบบกัน** และถ้าข้นเหนียวต้องเน้นล้างจมูกด้วยน้ำเกลือร่วมด้วย" |

**กฎใหม่ใน SYSTEM prompt:** ในทุกคำถาม/เหตุผลของการซักประวัติ (รวมหัวข้อ "ข้อมูลที่ควรซักเพิ่มเติม") **ห้ามเอ่ยชื่อยาเฉพาะตัวหรือชื่อกลุ่มยาทางเลือกเป็นตัวอย่าง** พร้อมเหตุผล (ยังไม่ได้ตัดสินใจเลือกยา + ยกมาไม่ครบ = bias) และระบุ **ข้อยกเว้นเดียว** คือคำถามที่ตัวคำถามเองคือการถามชื่อยาของผู้ป่วย และการอธิบาย *กลไก* ที่เป็นสาระของคำถามนั้น (ไอแห้ง vs ไอมีเสมหะ)

### 3.3 แก้ข้อ 3 -- Centor ใช้เฉพาะ pharyngitis

เพิ่มฟังก์ชัน **`centor_scope(f)` (13 บรรทัด)** เป็นประตูเดียวของเกณฑ์ Centor แล้วให้ทุกจุดที่เคยเช็ค `sore_throat` เองเรียกผ่านมันแทน:

```
centor_scope(f):
  ไม่มี sore_throat            -> (False, "")            # เหมือนเดิม
  อายุ < 3 ปี                  -> (False, "child3")      # เหมือนเดิม
  hoarse=True และ **ไม่มี**สิ่งตรวจพบบ่งชี้ GABHS
  (ทอนซิลบวม/มีหนอง หรือต่อมน้ำเหลืองคอด้านหน้าโต)  -> (False, "laryngitis")   # ใหม่
  นอกนั้น                      -> (True, "")
```

- เพิ่ม `f["tonsil_finding"]` / `f["lymph_finding"]` ใน `extract_case_features()` (ใช้ regex เดิมของ Centor ไม่ได้เขียนใหม่)
- จุดที่ถูกกันทั้งหมด (5 จุด): `centor_assessment()`, `centor_note()`, คำถามซักประวัติที่อ้างเกณฑ์ Centor (ไอ/ทอนซิล/ต่อมน้ำเหลือง/อายุ/ไข้), ประโยคปิดท้ายของเทิร์นซักประวัติ (`ask_first_reply`), และ `practice_flags()` (Expert Opinion RDU)
- **แต่ยังต้องรู้ว่ามีไอไหม** -> เคสคอ/เสียงแหบที่อยู่นอกขอบเขต ยังถามคำถามเดิม แต่เปลี่ยนเหตุผลเป็น *"เพื่อประเมินอาการร่วมและเลือกยาบรรเทาอาการให้ตรง"* (ไม่อ้าง Centor)
- `centor_note()` ส่งบล็อกใหม่เข้า Context ว่า **"Modified Centor -- ไม่ต้องประเมินในเคสนี้"** พร้อมเหตุผลจาก AAFP + สั่งให้ใช้เหตุผลของ laryngitis ตรงๆ แทน
- SYSTEM prompt เพิ่มหัวข้อ **"ขอบเขตของเกณฑ์ตาม Context"** (อ้างประโยค *"when evaluating patients with pharyngitis"* ตรงจาก AAFP) + แก้อีก 3 จุดที่พูดถึง Centor ให้สอดคล้อง

### 3.4 (พบระหว่างทดสอบ) บั๊กเลขหน้า `[Ref: Dose]` -- แก้ให้ตรงตามข้อจำกัดของโจทย์

ระหว่างรันเคสที่ 1 พบว่าคำตอบเขียน **`Ibuprofen ... [Ref: Dose, หน้า 8]`** ทั้งที่ Ibuprofen อยู่ **หน้า 10** (หน้า 8 = Paracetamol) -> กดอ้างอิงแล้วเปิดผิดยา

- **เป็นบั๊กเดิม ไม่ได้เกิดจากการแก้รอบนี้** (อยู่ใน `_line_dose_pages()` / `_last_drug_hit()` ซึ่ง diff รอบนี้ไม่ได้แตะมาก่อนหน้า) แต่เข้าข่ายข้อจำกัด *"เลขหน้าอ้างอิงห้ามโดนเด็ดขาด"* จึงแก้ให้ในรอบนี้
- **สาเหตุ:** `_last_drug_hit()` เลือก "ชื่อยาที่ยาวที่สุดในบรรทัด" (กฎที่ทำไว้ให้ชื่อผลิตภัณฑ์ชนะชื่อสามัญ) -- พอบรรทัดอธิบายยาเอ่ยชื่อยาตัวอื่นประกอบ เช่น
  `- **Ibuprofen:** เหมาะกับคนที่ใช้ Paracetamol แล้วไม่ดีขึ้น [Ref: Dose]` -> `Paracetamol` (11 ตัวอักษร) ชนะ `Ibuprofen` (9) -> chip ชี้หน้า 8
  และบรรทัดย่อย `ขนาด: ...` ที่ไม่มีชื่อยา ก็ไปหยิบหน้าเดียวกันต่อจาก window 300 ตัวอักษร
- **การแก้ (2 ฟังก์ชันใหม่ ไม่แตะกฎเดิม):**
  - `_label_drug_page(line)` -- ยาที่อยู่ **ตำแหน่งหัวข้อของบรรทัด** (`- **ชื่อยา:** ...`) คือเจ้าของ `[Ref]` บรรทัดนั้น ให้ชนะก่อนเสมอ
  - `_recent_drug_page(before)` -- บรรทัดที่ไม่มีชื่อยา (`ขนาด: ...`) ให้ไล่ย้อน **ทีละบรรทัด** หาหัวข้อยาล่าสุด แทนการเทียบความยาวข้ามบรรทัด
  - ถ้าหัวข้อไม่ใช่ชื่อยา (`ยาแก้ปวด/ลดไข้:`, `ขนาด:`) จะ fallback ไปกฎเดิมทุกประการ -> **กฎ "ชื่อผลิตภัณฑ์ชนะชื่อสามัญ" ยังทำงานเหมือนเดิม** (ทดสอบยืนยันแล้ว: `Strepsils dry cough (Dextromethorphan)` -> หน้า 42 ไม่ใช่ 36)

## 6. ข้อจำกัด / ความเสี่ยงที่เหลือ

1. **การตัดสินว่า "เคสนี้เป็น laryngitis หรือ pharyngitis" ใช้ rule-based** -- เกณฑ์คือ *มี "เสียงแหบ/สายเสียงอักเสบ"* และ *ไม่มีสิ่งตรวจพบบ่งชี้ GABHS (ทอนซิลบวม/มีหนอง, ต่อมน้ำเหลืองคอด้านหน้าโต)* ถ้าอาจารย์เห็นว่าควรใช้เกณฑ์อื่น (เช่น ให้เสียงแหบ "เป็นอาการนำ" เท่านั้น) แก้ได้ที่ `centor_scope()` **จุดเดียว** -- ทุกจุดที่ใช้ Centor อ่านจากฟังก์ชันนี้หมดแล้ว
2. **เคสที่เป็นทั้ง laryngitis และ pharyngitis พร้อมกัน** -- ตอนนี้ถ้ามีสิ่งตรวจพบ GABHS ร่วม ระบบจะยังใช้ Centor (เผื่อความปลอดภัยฝั่งไม่พลาด strep) ควรให้อาจารย์ยืนยันว่านี่คือพฤติกรรมที่ต้องการ
3. **กฎยาแก้แพ้รุ่นที่ 1 vs 2 อิงคอลัมน์ `first_gen` ของ formulary** ซึ่งมาจากรายชื่อตัวยา (CPM, brompheniramine, diphenhydramine, cyproheptadine, hydroxyzine) -- ถ้าตาราง Dose เพิ่มยารุ่นที่ 1 ตัวใหม่ ต้องเพิ่มชื่อใน `_FIRST_GEN_AH` ด้วย (1 บรรทัด)
4. **LLM ยังมีความไม่แน่นอนตามธรรมชาติ** -- ข้อตรวจเชิงโครงสร้าง/เลขหน้าเป็น deterministic แล้ว แต่ถ้อยคำอธิบายยังแปรตามรอบ
5. **ยังไม่ได้แก้กฎเรื่อง "ไม่ยกตัวอย่างยา" ในหัวข้ออื่นนอกขั้นซักประวัติ** -- ตั้งใจไม่แตะ เพราะขั้นแนะนำการรักษา **ต้อง** มีชื่อยาและขนาดยา (ตาม feedback รอบก่อนๆ)

## 7. Next Steps (ไม่ควรมีปัญหาเพิ่ม)

1. ให้อาจารย์ลองยิงเคสจริงหน้าร้านชุดเดียวกับรอบนี้ โดยเฉพาะ **เคสน้ำมูกข้นเหนียว** (ดูว่าเสนอรุ่นที่ 2 ตัวไหนบ้าง ตรงกับที่ต้องการไหม) และ **เคสเสียงแหบ** (ดูว่าเหลือคำถามครบพอไหมหลังตัดคำถาม Centor ออก 2 ข้อ)
