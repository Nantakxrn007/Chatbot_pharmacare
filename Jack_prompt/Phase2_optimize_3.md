Optimize: การแก้ไขในรอบนี้ ฉันต้องการให้แก้ไขเฉพาะจุดเล็กน้อย เหมือนด้านบนเท่านั้น (และเคสอื่นอื่นที่ใกล้เคียงกัน), โดยยังเป็นจุดเล็กๆน้อยๆ โดยเฉพาะการยกตัวอย่างที่มี เอาไปรวมกัน (เหมือน case 1) และยกตัวอย่างไม่หมด (เคส 2), ควรแก้ไขเคสประมาณด้านบน (การแก้ไขควรครอบคลุมทั้งเคสด้านบนและเคสที่ใกล้เคียงที่มีโอกาสได้ query เข้ามาในอนาคตด้วย)


ลองดู pattern สำหรับเคสที่ยกตัวอย่างมันเป็นยังไงแล้ววิเคราะห์ และแก้ไข เพ่อความแม่นยำสูงสุด


=== Optimize Constraint ===
ข้อจำกัดที่ฉันไม่อนุญาตให้คุณทำ
1. แก้ไข chunk หรือมีการทำ chunking ใหม่ หรือ Ingestion ใหม่ คุณสามารทำได้เพียง เช็ค ทดสอบ ลองดู เทส เท่านั้น ห้าม edit หรือ ลบ หรือ add เข้ามาใหม่
2. การ optimize พยายาม based ต่อจากของเดิม ไม่ควร refactor ใหม่หมด (อาจเกิดความเสีบหายต่อสิ่งที่ดีอยู่แล้ว)
3. เน้นย้ำ ข้อมูล ต้องถูกต้อง ครบถ้วน หลากหลาย
4. การแก้ไขระหว่างโดนหรือกระทบส่วนอื่นที่ดีอยู่แล้ว อย่างเช่น เลขหน้าอ้างอิง (อย่าให้โดนเด็ดขาด (ควรตรงทุกหน้า))



ตอนนี้ระบบค่อนข้างทำได้ดีและพร้อมในระดับนึงแล้ว การแก้ไขในครั้งนี้พยายามอย่าแก้ไขจุดที่ไม่ได้บอก หรือจุดที่แก้ไขแล้วบบางอย่างจะเปลี่ยนไป (ฉันอนุญาตเฉพาะจุดประมาณด้านบนเท่านั้น) เนื่องจากฉันไม่ต้องการให้ระบบพัง **เน้นย้ำ** อย่าแก้จุดที่ไม่จำเป็นหรือไม่ได้บอก




พยายามลบไฟล์ที่ไม่จำเป็นออกหลังจากไม่ได้ใช้หรือไม่เกี่ยวข้องกับ main project


ระวังเรื่อง limit ของ Claude Opus (Planning ให้ดี)


Agnt Flow:
1. อ่าน prompt นี้ให้เข้าใจ
2. ลองดูสิ่งที่ทำมา (ดูว่าจากเดิมเป็นอย่างไรจนถึงปัจจุบัน (แต่ปัจจุบันดีสุด เหลือแค่ปัญหาเล็กๆคล้ายๆด้านบน))
3. ลองดูข้อมูลทั้งแบบไฟล์ปกติ และ chunk embedding (ดูเพื่อเข้าใจเท่านั้น)
4. Planning หา pattern วิเคราะห์สาเหตุ และออกแบบ plan สำหรับการ แก้ไขและปรับปรุงให้ดีขึ้นตาม feedback ล่าสุด
5. ลอง Enhance และหา planning ที่ดีที่สุด และ optimize ตามนั้น
6. ทดสอบกับเคสเก่าและเคสใหม่
7. ทดสอบระบบ (ห้ามแย่ลงและต้องดีขึ้นเท่านั้น)
8. ระบบไม่ควรเปลี่ยนไปมาก (ควรคล้ายเดิม) เนื่องจากเป็นการแก้ไข detail เล็กน้อยเท่านั้น
9. ตรวจสอบอีกครั้ง
10. สรุปผลและเขียนผลลัพธ์
11. Clear ไฟล์ที่ไม่จำเป็นออก (ที่ไม่ได้เกี่ยวข้องกับ main project)
